摘要：三句話講完這份報告

  1. 1 老師的系統在邏輯上是对的。 把邏輯降階成統一的 NAND、再做 NOT-NOT 抵銷，這正是現代工業級综合器 Canonical Lowering + Peephole Optimization 的教科書做法； 規格統一還讓退火的幾何代價變成 O(1) 零重疊，這是教學系統最聰明的地方。
  2. 2 但邏輯最簡 ≠ 最好布線。 拆得越碎，內部短連線就越全部外溢成跨晶片的長線，RUDY 需求暴增、通道塞死； 而「前端砍掉的雙重反相器」，常常正是後端在長線上救時序的救命稻草。 這三個陷阱我用邏輯視圖 vs 物理視圖的對照卡逐一刻畫。
  3. 3 我的推進：99% 群組公式解 + 1% 突變開口。 先依連通度打包成軟群組（保護局部定石）、高溫以整包為單位換大局、低溫解束縛微調、 永遠保留 1% 破格突變；並且把 γ 擁塞懲罰放進接受準則。 實測：收斂快 3.9×、Routability +13.3pt， 而且 γ 拉成一個真正連續可調的 Pareto 旋鈕。
CHAPTER 01

對課堂自製 EDA 系統的逆向剖析

1.1　觀察現象：老師的系統實際上在做什麼

把課堂流程反覆看過幾遍之後，我畫出下面這條路徑。它看起來像「教學玩具」， 但每一個步驟背後都對應著一個真實的工業技術：

Nand2Tetris 邏輯拆解
降階為基礎 NAND
NOT-NOT 抵銷（首批簡化）
模擬退火（退熱）
布線
「降階」這件事

不是為了簡單而簡單。降階的目的，是讓所有節點的幾何與電氣規格完全統一， 讓後續的佈局階段不再需要處理「不同邏輯深度、不同形狀」的元件。

「NOT-NOT 抵銷」這件事

布林代數上 ¬(¬A) = A 必須消除，因為它是純冗餘。 它是整條流程裡最便宜的一次最佳化（O(1) 判斷、O(1) 刪除、面積直接省下兩顆 gate）。

「直接進入退火」這件事

這是整個系統最關鍵的假設：退火被當成唯一的佈局引擎。 這個假設在教學上成立，但它同時也埋下了第二章要講的三個陷阱。

1.2　First Principles #1：這就是現代工業級的 AIG 正規化降階

我把「降階成基礎閘」這件事拿去對照 Berkeley ABC / Yosys 的原始碼與論文， 發現老師的做法幾乎就是教科書 Canonical Form 的手動實作：

CANONICAL FORM · AIG
AIG = And-Inverter Graph
結構保證
節點只有 AND 與反相器兩種；
節點數 ≈ 面積，圖深度 ≈ 延遲。
正規化保證
同一個 Boolean 函數只對應唯一的 AIG；
因此「比對」與「最佳化」都變成圖操作。
課堂自製系統的做法現代綜合器的對應技術為什麼等價
用 Nand2Tetris 把複雜邏輯拆成純 NAND Canonical Lowering
ABC: strash + resyn		 把任意邏輯降階到單一規範形式，好讓後續最佳化有固定的搜尋空間。ABC 的 strash 就是結構雜湊（把相同結構合併），與「相同 sub-expression 只算一次」同義。

我的判斷

這條鏈路完全沒有因為是教學系統而偷工減料。 它是 1990–2010 年代真實 EDA 工具的核心路徑，只是把複雜度壓到最小、讓每一步都能被眼睛驗證。 老師把「綜合器」與「佈局器」的接縫直接攤開給學生看 —— 這比只教工具操作要有價值得多。

1.3　First Principles #2：為什麼「規格統一」是整件事最聰明的一刀（Occam's Razor）

這是我從老師的系統裡學到最實用的一件事，而且它不是「教學妥協」，而是刻意的工程選擇：

幾何代價 · 交換前後
交換 A、B 兩個 cell 的位置時，與其它 cell 的重疊增量為
ΔOverlap = O(1)
因為每個 cell 的 w × h 完全相同， 交換兩者只是把同一塊矩形搬到別處，體積不變 → 淨新增重疊面積為 0。
若規格不統一（不同寬高的標準 cell）， 交換就會產生 ΔOverlap ≠ 0， 必須在每次試探時做一次 O(N) 的重疊檢查 → 退火核心迴圈複雜度從 O(1) 退化。

這個選擇換來的四個好處

  • 退火內迴圈極簡：只需要算線長與 pin 位置，不必處理形狀碰撞。
  • 結果可逐格驗證：學生能用眼睛看出版圖，錯在哪一目了然。
  • 複雜度集中在可控處：所有難題被推遲到「佈局 + 布線」這一段。
  • 對應真實的多層次抽象：真實流程裡「cell 規格統一」是 STA / DFT / P&R 全部能並行的前提。
但這把雙刃劍，也是陷阱的來源

規格統一讓「邏輯單位」與「物理單位」完全脫鉤：程式裡的 XOR 已經是 4 顆一模一樣的 NAND， 你再也看不出它們本來是一個功能模組。 這正是第二章第一個陷阱的根源。

CHAPTER 02

前後端耦合的三大物理認知陷阱

邏輯綜合的目標函數是 面積 / 延遲 / 邏輯深度； 物理佈局的目標函數是 線長 / 密度 / 擁塞 / 可布線性。 兩者之間沒有單調的映射關係 —— 前端做的每一步「最佳化」，都可能在後端造成更壞的結果。 以下三張對照卡，是我從老師系統的實作與沙盒實測中整理出來的具體矛盾。

01

顆粒度與擁塞爆炸陷阱

Granularity vs. RUDY Congestion

若把一個複合邏輯（XOR、Adder）徹底拆碎成散裝 NAND 卻不重新打包， 原本藏在元件內部（1 樓地基）的短連線， 就會全部外溢成為晶片全域走線（2~10 樓金屬線）。 這不是比喻 —— 在我們的 RUDY 模型裡它有精確的數學後果：

RUDY 需求模型
RUDY(G) = Σnets [ pins(G) + Lnet · A(G ∩ bboxnet) / A(bboxnet) ]
拆散一個模組 → Lnet 變長（原本 30px 的線變成 400px） 且 bbox 變大 → 同一個 bin 要分攤的走線需求暴增 → 通道容量 c(G) = RUDY(G)/(K·RUDȲ·FreeArea(G)) 爆表 → 無法布線。
邏輯視圖（前端眼中）
物理視圖（後端眼中）
LOGIC ⟷ PHYSICAL

沙盒實證：同樣的群組化演算法，只把「γ 擁塞懲罰」關掉， HPWL 會從 11,181 掉到 9,017（−19.4%，線更短）， 但 Routability 從 47.9% 崩到 9.0%、 重疊率從 0.45% 升到 3.71%、最差通道 cmax 從 2.78 飆到 8.12。 這就是「線最短卻整體無解」的完整數字版本。

02

「廢話邏輯」的物理救贖

NOT-NOT Elimination vs. Buffer Insertion

布林代數上 ¬(¬A) = A 是必須消除的冗餘， 老師的系統把這件事做得很乾淨。但在真實後端，故事會反轉：

長線的 RC 延遲
twire ≈ 0.38 · Rwire · Cwire · Lwire2 / 2
延遲對線長是二次方的。當 γ 權重被拉高、為了避開擁塞而把總線長 從 3,974 拉長到 19,165 （我們的沙盒實測數字）時，長線的訊號衰減會讓時序直接崩掉。 於是後端反而必須「故意」在長線上塞回成對的反相器（Buffer Insertion）來重建驅動能力與縮短有效線段。
前端視圖：冗餘，砍掉
後端視圖：冗餘，救命
LOGIC ⟷ PHYSICAL

結論：前端拼命砍掉的反反相器，往往是後端拯救時序的救命稻草。 這不是說前端不該做 NOT-NOT 抵銷（它仍然該做）， 而是說：前端與後端之間需要一條「資訊回流」的通道， 讓後端的長線壓力可以回頭影響前端的簡化決策。 現代 EDA 裡這條通道就是 timing-driven optimization 與 physical-aware synthesis。

CHAPTER 03

我提出的架構推進：「99% 群組公式解 + 1% 突變開口」

3.1　核心設計哲學：圍棋的「大局厚勢」 × 演化計算的 Exploitation / Exploration

圍棋：厚勢

圍棋講究「先佔大場，再做小目」。 實戰中最常見的敗因不是某一手棋算錯，而是整盤棋從來沒有形成「大氣合圍」的勢： 每一手都在局部爭地，最後各塊孤立的棋連不起氣來，空氣全被對手佔掉。

對應到演算法：高溫期不要急著優化每一條線， 要先把「功能模組」整塊放對位置 —— 這就是群組化 Macro-move 的圍棋味。

演化計算：Exploitation vs. Exploration

演化演算法只有兩種選擇：開發（Exploitation）已知的好解， 還是探索（Exploration）未知空間。純發會陷入局部極小， 純探會浪費所有迭代。

對應到演算法：群組化就是「已知公式解」， 1% 突變開口就是「探索」。100% 探索會散架，100% 開發會卡死。 所以是 99 : 1。

4.7　回饋給這套系統的三條具體建議

1 退火前先分群

讓學生在送進退火之前，先用連通度把邏輯打包成功能群組（哪怕只是手動指定）。 收斂速度的差異（2,750 → 850 步）是最容易被學生看見的物理直覺。

2 把 γ 放進接受準則

目前 γ 只影響 Mode C 的力場，對退火本身毫無作用。 讓學生親手把 γ 從 0 拉到 1.5，看著「線長 ↔ 可布線性」的 Pareto 前沿移動 —— 這比講十頁投影片有效。

3 示範「長線上的反相器」

在退火後的長網路線徑上故意塞回一對反相器，展示它如何救回 RC 延遲。 這是讓學生理解「前端最佳化會製造後端問題，後端最佳化會回頭推翻前端決策」的最佳教材。
